# MA-BEMS · 멀티에이전트 건물 에너지 관리 시스템

[English](README.md) · 한국어

**라이브 대시보드: https://sunghyunc.github.io/ma-bems/**
(공개 사이트 배포 저장소는 [SungHyunC/ma-bems](https://github.com/SungHyunC/ma-bems), 이 저장소는 프로젝트 전체 원본)

6개 에이전트(코디네이터·HVAC·조명·태양광·ESS·EV 충전)가 15분마다 관찰→계획→조율→실행→검증을 반복하고, 부딪히는 계획은 코디네이터가 우선순위로 정리하며
가상 캠퍼스(Helio Campus)의 피크·요금·쾌적을 함께 관리합니다. 같은 날씨·재실·EV·DR 신호로 룰 기반 BMS를 나란히 돌려
차이만 비교합니다(반사실 그림자 실행). 고려대 세종 2026-2 기업연계형 캡스톤디자인 출품작입니다.

## 결과 한눈에 (시뮬레이션 기준, 9일 × 1분 단위, 1~8일 채점)

± 읽는 법: 입력이 고정된 한 번의 실행에서 "± 0.2"는 그 8일 일별 값의 95% 구간(t)이라 **일별 변동만** 뜻합니다. 입력이 달라져도 유지되는지는 시드 10회(`?seed=N`: 재실·EV·DR 시각을 다시 뽑고 날마다 날씨가 달라짐)의 실행 간 95% 구간이 맞는 척도입니다.

| 항목 | 에이전트 vs 룰 기반 BMS |
|---|---|
| 전력량요금 절감 (기본 BMS) | **16.7 ± 0.2%** (1회 실행, ± = 8일 일별 변동). 시드 10회 **16.5 ± 0.2%** (실행 간 95% 구간) |
| 튜닝 BMS (ESS 피크 제어 추가) | 16.6 ± 0.4%. 기본 BMS와 비용이 거의 같고 평균 최대 수전은 조금 높음(1,176 vs 1,170 kW)이라 강한 기준선이라 하기 어려움 |
| 센서 BMS (에이전트와 같은 재실 센싱 + ESS 피크 제어 + 고정 DR 대응) | **9.7 ± 0.3%** (시드 10회 10.2 ± 0.2%). 그 BMS의 쾌적은 97.0%(시드 97.4%)로 낮아짐. `dr=off`에서는 14.4%라, 16.7% 중 약 2.3%p는 DR 미대응 효과 |
| 최대 수요 | 일별 최대의 평균 959 vs 1,170 kW (기간 최대는 약 960 vs 1,210 kW). 시드 10회 981 vs 1,193 kW. 8일간 한도 1,000 kW 초과 0분 vs 1,996분 |
| 쾌적 | 99.9% vs 100% (시드 10회 99.7 vs 99.9%) |
| 수전 예측 (1시간 앞, 미래 날씨 미사용) | CV(RMSE) 8.0%, NMBE 0.1% (n = 766). 어제 같은 시각 9.0%, 1시간 전 값 유지 14.1%. 시드 10회 8.0 / 9.9 / 12.9%. ASHRAE Guideline 14의 30%는 에너지 모델 보정 기준이라 "기준 이내"가 아니라 참고 비교 |
| 센서 고장 감지 | 정상 운영 오경보 0건/1,206 실·일(기본 입력). 기본 입력 무고장 25회 합계 6건/30,150 실·일. 센서 노이즈 0.3 °C에서 1건/1,206, 훈련 63/64 감지. 훈련은 경보의 진위를 아는 운영자를 가정. 날씨 변동 시드 10회에서는 12,060 실·일에 34건(한 시드에 14건) |
| 기본요금 (한전 8,320원/kW·월, 기간 최대 기준) | 기본 비용에는 없음. 넣으면 한전 요금·모델 부하 14.9 → 15.5%, BDG2 부하 형태 14.6 → 15.6%. 저장소에 달러 요율이 없어 달러 계산은 매개변수 |

BDG2는 미국 대학 건물 4개의 여름 평일 하루 실측 비-HVAC 전력을 헬리오 캠퍼스에 맞춰 크기를 조정해 매일 반복한 것이며, 이 캠퍼스의 실측 부하가 아닙니다.

- 코디네이터 v1(우선순위 조율)은 기본 한도에서 추가 절감이 없고(−0.15%p), 한도가 빠듯할 때 효과가 납니다. 초과 전력: 900 kW 482 → 417 kWh(−13%), 850 kW 2,129 → 1,675 kWh(−21%), 800 kW 5,083 → 4,610 kWh(−9%).
- **코디네이터 v2** (`?coord=v2`, 선택형, 기본값은 v1): DR 예고 + 배터리 예비·단계적 복귀, 예측 기반 ESS 배분, 비용 기반 배분(최대 3라운드). v1 대비: 평상시 16.7 → 17.4%, 최악의 날 9.8 → 15.9%·평균 최대 수전 1,512 → 1,299 kW(BMS 1,454보다 낮음), 한도 850 초과 1,675 → 392 kWh, 한도 800 기간 최대 1,157 → 950 kW, 시드 10회 +0.4 ± 0.1%p·기간 최대 −66 ± 26 kW. 나빠진 곳: 한도 초과 시간이 늘어남(폭염 +61%, 최악의 날 +50%, 한도 800 +88%), 한도 850 절감 −0.6%p. 기본값 전환 여부는 미정.
- **고장의 에너지 영향** (`?faultImpact=1`, 9일, 진짜 경보만 승인하는 운영자): 드리프트 고장은 감지 끔 +1,285 kWh, 켬 +27 kWh. 3시간마다 고장을 넣는 훈련은 감지 끔 +12,387 kWh(주입 49건) vs 켬 +1,572 kWh(주입 63건)라 같은 고장 수의 비교는 아님. 한계: 가상 센서에는 피드백이 없어 방치한 고착은 404 kWh를 아끼지만 불쾌 1,963 °C·h가 늘고, 닫힌 루프에서 드리프트 감지는 55 → 245분(중앙값)으로 늦어지며 훈련에서 오경보 55건.

시나리오 9종(폭염·흐린 날·DR·한도 하향·EV 몰림·휴일·센서 고장·최악의 날)별 결과와 한계는 [eval/README.md](eval/README.md).
절감은 아직 계량 데이터로 보정하지 않은 시뮬레이션 값입니다. 데모 영상은 이 변경 전에 만들어져 예전 문구·수치(예측 11.0% 등)가 남아 있을 수 있습니다(설명서 PDF는 2026-11-12에 다시 만듦).

## AI 비서와 파인튜닝: 측정한 것과 못 측정한 것

- 학습에 쓰지 않은 조건 234건(`eval`)의 "조건"은 새롭지만 질문 문장 234건 중 226건은 학습에도 있습니다. 처음 보는 문장 세트(`eval_gen`, 234건, [ft/README.md](ft/README.md))에서 v2.1은 수치 검사 99.1%, 핵심 숫자 96.4%, 한 문장 지시 100%, 답할 수 있는 질문 거절 0.4%.
- 수치 검사는 숫자가 모델에 준 데이터에 있는지만 보며 정확도 측정이 아닙니다. 질문 뜻 이해도 재지 않습니다.
- 실제 예상 질문 66개(41.5 → 62점, 오답 17 → 0)는 수정을 이 질문에 맞춰 한 회귀 세트라 일반화 점수가 아닙니다.
- 게이트웨이: `/v1/chat/completions`는 관리자 키 전용, 프롬프트 추출 검사는 모든 작업에 적용, 로컬 포트는 Origin·Content-Type 검사, 스트리밍 전 유출 검사, "한도를 넘을까?"는 예측 경로로 답함. `numcheck`는 숫자를 라벨에 묶고 잘못된 숫자 형식을 거절합니다(저장된 v2.1 출력의 통과율은 모든 세트에서 같고, 66개 실제 질문에서는 실제 오류 3건을 새로 잡았으며 1건은 저장된 문맥이 달라 판정 못 함). `server/test_gateway.py`에 테스트 8개.

| 폴더 | 내용 |
|---|---|
| `index.html` | 대시보드 (단일 파일, Three.js). 브라우저에서 시뮬레이션·에이전트·예측·고장 감지가 모두 돌아감 |

| `deploy/` | 공개 배포 스크립트(GitHub Pages + Cloudflare 터널, 접근 키) — 운영 가이드 [deploy/README.md](deploy/README.md) |
| `ft/` | 로컬 LLM 파인튜닝(QLoRA): 시뮬레이터로 만든 학습 데이터, 학습·평가 코드, 결과 — [ft/README.md](ft/README.md) |
| `deck/` | 경진대회 발표자료 원본(슬라이드 HTML) |
| `docs/` | 프로젝트 설명서(PDF·HTML). 데모 영상 파일은 용량 때문에 Releases에 둠 |
| `demo/` | 데모 영상 제작: 대본(`script.json`), 한국어 음성(`tts.ps1`), 자동 녹화(`record.mjs`), 합성(`assemble.py`) |
| `data/` | BDG2 실측 샘플(CC BY-SA 4.0) |
| [`HANDOFF.md`](HANDOFF.md) | 인수인계: 현재 상태, 결정 이유, 명령 모음, 남은 일 |

## 실행

```
python -m venv .venv && .venv\Scripts\pip install anthropic
copy .env.example .env          (ANTHROPIC_API_KEY 등 채우기, Ollama에 qwen3 8B 모델)
.venv\Scripts\python server\mabems_server.py      → http://127.0.0.1:5178
```

AI 비서 없이 보기만 하려면 `index.html`을 정적 서버로 열어도 됩니다(시뮬레이션은 브라우저에서 동작).
