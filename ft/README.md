# MA-BEMS 로컬 LLM 파인튜닝 (QLoRA)

AI 비서의 로컬 모델(Qwen3-8B)을 MA-BEMS 데이터 형식과 운영 규칙에 맞게 추가 학습합니다.
기반 가중치는 얼려 두고 LoRA 어댑터(약 0.5%의 추가 가중치)만 학습해, 16 GB GPU 한 장으로 끝납니다.

## 왜 하나

- 공개 사이트의 접근 키(judges)는 로컬 모델만 씁니다. 8B 모델은 제어 제안에서 대상 칸에 `ess`·`roomLights` 같은 값을 넣어
  16건 중 0건이 유효했습니다. 이것은 출력 제한(실제 ID만 고르게 하는 문법 제약)으로 이미 막았습니다(14/14 유효).
- 남은 문제는 **내용**입니다. 제안은 유효해졌지만 이미 꺼진 방의 조명 끄기 같은 효과 없는 조치가 많고,
  답변이 형식(결론 한 문장 + 근거 2~4줄)을 자주 벗어나며, 데이터에 없는 숫자를 쓰기도 합니다. 파인튜닝은 이 부분을 겨냥합니다.

## 학습 데이터 (API 비용 0원)

1. `scripts/collect.mjs` — 시뮬레이터를 시나리오 9종 + 무작위 조건 31종으로 돌리며, AI 패널이 실제로 보내는 문맥(chat·propose·explain)을
   45~60분 간격으로 기록합니다 (`data/samples_train.jsonl`, 782건). 평가용은 다른 무작위 조건 6종 (`data/samples_eval.jsonl`, 117건).
2. `scripts/make_data.py` — 그 문맥만 보고 규칙으로 정답을 씁니다. 숫자는 모두 문맥에 있는 값이고, 서버의 수치 검증(`numcheck`)을
   전부 통과합니다(학습 1,214/1,214, 평가 177/177).
   - 질의응답 13종(피크 여유, 비용, 건물, ESS, 태양광, 쾌적, 에이전트, 날씨, DR, 고장, 예측, 영어 2종) + 데이터에 없는 질문엔 "데이터에 없음"
   - 운영 브리핑, 선택 대상 설명(건물·층·방)
   - 제어 제안: 압박 상황(DR, 여유 12% 미만, 예측 95% 이상, 피크 요금에 여유 20% 미만)엔 재실 낮은 층 +1 °C,
     빈 방 조명 끄기, 회의 예약 사전 공조가 아닌 빈 방의 냉방 셋백. 효과 없는 조치는 내지 않고, 없으면 "바꿀 필요 없음"
   - 결과: 학습 1,592건, 평가 234건
   - 한계: 정답이 규칙에서 나오므로 모델은 그 규칙과 문체를 배웁니다. 규칙보다 똑똑해지지는 않습니다.
     Claude 답변을 정답으로 쓰는 방법도 있지만, Anthropic 약관의 경쟁 모델 학습 제한에 걸릴 수 있어 쓰지 않았습니다.

## 학습

- 기반: `Qwen/Qwen3-8B`(공식, Apache-2.0) — Ollama의 `qwen3-8b-local`(Q4_K_M)과 같은 원본
- QLoRA: 4비트 NF4로 얼린 기반 + LoRA r=16(α=32, 모든 attention·MLP 투영), 학습률 2e-4(cosine), 답변 부분만 손실 계산
- 메모리: 어휘 확률(152k)은 답변 위치에서만 계산합니다(`AnswerOnlySFTTrainer`). 프롬프트 전체에 계산하면 약 3 GB가 더 들어,
  데스크톱과 GPU를 나눠 쓰는 16 GB 카드에서 시스템 메모리로 넘치며 4~30배 느려졌습니다. 바꾼 뒤 단계당 25초, 최대 8.4 GB
- 데이터: 3,328토큰 이하 예시 중 유형별로 뽑은 946건, 1회 학습(119단계, 약 50분)
- 프롬프트는 Qwen3 채팅 템플릿(think 끔)으로 만들며, Ollama가 게이트웨이 요청을 렌더링한 토큰 수와 같음을 확인했습니다(2,414 = 2,414)

```
.venv\Scripts\python scripts\train.py --model models\Qwen3-8B --data data\train_sub.jsonl --out out\qwen3-bems-lora --epochs 1 --max-len 3328
.venv\Scripts\python scripts\merge.py models\Qwen3-8B out\qwen3-bems-lora out\merged
.venv\Scripts\python llama.cpp\convert_hf_to_gguf.py out\merged --outtype q8_0 --outfile out\qwen3-bems-Q8_0.gguf
ollama create qwen3-8b-bems -f out\Modelfile
```

Ollama 0.40은 별도 LoRA 어댑터(`ADAPTER`)를 더 받지 않고, 자체 양자화도 int4·int8·nvfp4 등만 지원해 Q4_K_M을 만들 수 없습니다.
그래서 어댑터를 원본 가중치에 합친 뒤 llama.cpp 파이썬 변환기로 Q8_0 GGUF를 만들었고, 공정한 비교를 위해 원본도 똑같이
Q8_0으로 변환해 `qwen3-8b-q8`로 등록했습니다(`out\Modelfile.base-q8`). Q4_K_M을 원하면 llama.cpp의 `llama-quantize`가 필요합니다.

## 평가

`scripts/eval_ab.py`가 게이트웨이와 같은 방식(같은 시스템 프롬프트·문맥, think 끔, 온도 0.3, 제안엔 ID 제약 스키마)으로
학습에 쓰지 않은 조건 234건을 두 모델에 묻고 채점합니다: 수치 검증 통과율, 형식, 언어, 핵심 숫자 재현율, "데이터에 없음" 거절,
제안의 무효 조치·부하 증가 조치·정답 정책과의 일치(정밀도·재현율)·"바꿀 필요 없음" 판단, 응답 시간.

**학습하지 않은 자유 질문 6개 점검 (정성)** — 학습 모델의 한계:
- 답할 수 있는 질문도 거절함: "오늘 가장 비싼 시간대는?" → "데이터에 없음"(실제로는 피크 13–19시가 데이터에 있음). 원본은 답했지만 내용이 틀림.
- 형식 지시를 따르지 않음: "한 문장으로만 요약" → 학습한 결론 + 근거 줄 형식으로 답함. 원본은 한 문장으로 답함.
- 다른 작업의 문구를 섞음: 냉방 1도 완화 질문에 제안용 문구("회의 예약 사전 공조 대상이 아님")가 섞임.
- 계산 추론은 둘 다 틀림("태양광이 없었으면 수전은?").

**해석**
- 대시보드 버튼 작업(브리핑·설명·제안·대표 질문)에서는 크게 좋아졌습니다.
  특히 숫자 근거(87 → 96%)와 효과 없는 제안(52% → 7%)이 그렇습니다.
- 자유 질문에서는 학습한 틀에 갇힙니다. 정답을 규칙 템플릿으로 만들어 말투와 질문 유형이 좁았기 때문입니다.
- "형식 준수"와 "핵심 숫자" 지표는 정답 템플릿의 형식을 기준으로 재므로, 학습 모델에 유리하게 기울어 있습니다.
- 개선안(v2):
  - 질문을 다양하게 바꿔 쓰기(같은 의도, 다른 문장)
  - 형식 지시("한 문장으로")를 따르는 예시
  - 답할 수 있는 질문을 거절하지 않는 반례
  - 제안 JSON 키를 Ollama가 강제하는 알파벳 순서로 학습
  - "바꿀 필요 없음" 예시 늘리기

**게이트웨이 교체**: `MA-BEMS\.env`의 `LLM_LOCAL_MODEL=qwen3-8b-bems` → `deploy\start-public.cmd -RestartGateway`.
그래픽 메모리를 5 GB에서 8.7 GB로 더 씁니다. 되돌리려면 `qwen3-8b-local`로 바꾸고 같은 명령을 실행합니다.

정리해도 되는 중간 파일(약 33 GB):
- `out\merged`: 어댑터로 1.6분이면 다시 만들 수 있음
- `out\*.gguf`: Ollama가 자체 저장소에 복사해 둠

## v2 (2026-11-10, Modal H100)

v1 결과의 개선안을 데이터에 반영해 다시 학습했습니다. 학습 코드(`scripts/train.py`, QLoRA r=16)는 v1과 같고, 데스크톱 대신 Modal GPU에서 돌렸습니다.

### 데이터 (`scripts/make_data_v2.py` → `data/v2/`)

1. **질문 다양화**: 의도마다 바꿔 쓴 질문 약 30개(한국어)와 15개(영어). 오픈 모델(DeepSeek, Fireworks)로 만들었습니다(`scripts/gen_paraphrases.py` → `data/paraphrases.json`).
   v1처럼 Claude 출력은 학습 데이터에 넣지 않았습니다. 답과 맞지 않는 질문(충전기별 빈자리 등)은 걸러냈습니다.
   의도별 20%는 학습에서 빼 평가에만 씁니다.
2. **형식 지시 따르기**: "한 문장으로만", "결론만" 같은 지시가 붙으면 결론 문장 하나만 답합니다(채팅 질문의 20%).
3. **답할 수 있는 질문은 답하기**: 새 의도 6종을 넣었습니다. 피크 요금 시간대·단가, 바깥 기온, 오늘 최대 수전, 탄소 배출량, EV 충전, 태양광 자가소비율입니다.
   v1이 거절하던 "오늘 가장 비싼 시간대는?"이 여기에 해당합니다. 정말 답할 수 없는 질문은 약 54개를 검토해 남겼습니다.
4. **제안 JSON 키를 알파벳 순서로 학습**: Ollama 문법은 `actions`를 `summary`보다 먼저 쓰게 합니다. 학습도 이 순서로 맞췄습니다.
5. **"바꿀 필요 없음" 예시**: 같은 문맥에서 빈 방을 이미 소등·셋백 상태로 바꾸면 정책상 할 일이 없어집니다.
   - v2: 이런 예시가 15%입니다.
   - v2.1: 32%로 늘렸고, 일부 방만 처리된 문맥도 추가했습니다.
- 정답 전부 수치 검증 통과(텍스트 1,925/1,925). 4,096토큰 이하만 사용. v2.1 학습 2,380건(제안 460건 중 빈 제안 146건).

**남은 문제와 권장 사항**
- 모델은 빈 방 셋백을 계속 제안합니다. 남은 오답 101건이 전부 같은 유형이었습니다(이미 `setback`이거나 `off`인 방에 `roomSetpoint`를 올리는 조치).
  같은 문맥에서 `hvacMode`를 잘못 읽고 "냉방 중"이라고 쓰기도 합니다.
- 그래서 게이트웨이가 후처리합니다(`server/mabems_server.py`의 `drop_noops`, 로컬·Claude 공통).
  - 지우는 조치: 공조가 `off`·`setback`인 방의 설정온도 올리기, 지금과 같은 설정온도, 이미 그 모드인 조명, 이미 어두운 방의 소등
  - 남는 조치가 없으면 요약을 "지금은 바꿀 필요가 없습니다"로 바꿉니다. 일부만 지웠으면 요약 끝에 몇 개를 뺐는지 덧붙이고, JSON에 `dropped` 개수를 넣습니다.
  - 정답 제안 895건의 조치는 하나도 지우지 않습니다.
  - 저장된 v2.1 출력에 적용하면 정밀도·재현율이 79.1 / 73.7%이고, 빈 제안은 37 / 37이 맞습니다.
- 평가는 bf16 vLLM 기준입니다. 운영 형식(Q8_0, Ollama)은 데스크톱에서 `eval_ab.py`로 다시 확인해야 합니다.
- 정답이 여전히 규칙 템플릿이라, 모델은 규칙보다 똑똑해지지 않습니다.

**데스크톱 적용**: 어댑터(`adapter_model.safetensors`, `adapter_config.json`)를 `out\qwen3-bems-lora-v21`에 둡니다.
