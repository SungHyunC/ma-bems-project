# 제어 기능 조합 비교

코디네이터 v2에서 11가지 운전 조건·제어 기능 조합을 기존 시뮬레이터로 실행했다. 1분 단위로 9일을 실행하고 첫날을 제외한 8일을 집계했다. 각 운전 조건에서 기상, 재실, 요금, 기본 BMS를 고정했다. 절감률은 8개 일별 전력량요금 절감률의 산술평균이다. 한도 초과 전력량은 8일 합계다.

| 운전 조건 | 구성 | 기본 BMS 대비 요금 절감률 | 한도 초과량 |
| --- | --- | ---: | ---: |
| 평상시, 1,000 kW | 기본 | 17.43% | 0 kWh |
| 평상시, 1,000 kW | `LIGHT,EV` | 16.45% | 0 kWh |
| 평상시, 1,000 kW | `ESS,LIGHT,EV` | 12.83% | 303 kWh |
| 한도 850 kW | 기본 | 17.27% | 392 kWh |
| 한도 850 kW | `LIGHT,EV` | 16.11% | 985 kWh |
| 한도 850 kW | `COORD,LIGHT,EV` | 16.04% | 1,399 kWh |
| 한도 850 kW | `ESS,LIGHT,EV` | 12.71% | 4,402 kWh |

`LIGHT`는 건물 단위 조명 디밍을, `EV`는 EV 충전 할당을 기본 규칙으로 돌린다. `ESS`는 저장장치의 에이전트 계획을, `COORD`는 코디네이터의 비용 기반 배분을 비활성화한다. 이 실험에서는 기능 조합을 바꾸고 효과를 측정했다. 최적 에이전트 수를 결정하려면 같은 제어 기능을 서로 다른 수의 에이전트로 묶거나 나눠 비교해야 한다.

[전체 결과표](summary.csv)에 저녁 EV 몰림 조건과 일평균 최대수전·쾌적률·충전 충족률을 포함했다.

## 재현

저장소 루트에서 Node.js 18 이상과 Python 3으로 실행한다.

```sh
node eval/followup/ablation/run.cjs
python3 eval/followup/ablation/summarize.py
```

각 실행은 `out/`에 일별 결과를 저장한다. 집계 결과는 `out/summary.csv`다. `run.cjs`는 저장소의 기준 실행 4개에서 일별 지표를 대조하고, 집계 스크립트는 같은 운전 조건의 일별 기본 BMS 지표가 모두 같은지 검사한다. 선택 실행에는 `normal`, `tight`, `evrush` 등 공통 이름 앞부분을 인수로 넘길 수 있다.
