# 오피스 재실 일정 민감도

MA-BEMS 저장소의 `d1e49eb916323389448369261752edb3a79b269f` 모델과 기본 코디네이터 v2, 원래 예측 및 센서 모형을 실행했다. 가상 캠퍼스의 건물과 설비, 합성 기상, 기본 시간대별 요금, 수요반응, 수전 한도 1,000 kW는 그대로 두었다. 각 비교에서 두 제어기에 같은 외부 입력을 주고 9일을 1분 간격으로 실행했다. 준비일을 제외한 8일을 집계했다.

`occ_office`만 1분 단위 시계열로 넣었다. 라이브러리 기본 사무 일정의 24시간 평균 재실률 입력(40.7958%)을 같게 유지했다. 수업 블록식 일정에는 08:15~19:30 사이에 수업 시간대와 짧은 휴식 구간을 모사했다. 늦은 근무 일정은 기본 사무 일정을 4시간 지연했다. 내장된 방별 프로필, 설비·열모델, 예약 생성과 기준 BMS 자체의 운용 규칙은 변경하지 않았다. 평균 재실률 *입력*을 맞춘 것이므로 사람 수 추정치까지 같을 필요는 없다.

각 수치는 캠퍼스 전체 결과다. 절감률은 8개 일별 전력량요금 절감률의 산술평균 `100 × (기준 BMS 요금 − MA-BEMS 요금) / 기준 BMS 요금`이다. 한도 초과 시간은 8일 합계다. 전력량요금에는 월 기본요금이 포함되지 않는다.

| 모의 오피스 재실 일정 | 기본 BMS 대비 절감 | 숙련 BMS 대비 절감 | 1,000 kW 초과 분, MA-BEMS / 기본 / 숙련 | 쾌적률, MA-BEMS / 기본 / 숙련 |
| --- | ---: | ---: | ---: | ---: |
| 기본 사무 일정 | 17.4% | 4.9% | 0 / 1,996 / 0 | 99.9% / 100.0% / 96.3% |
| 수업 블록식 | 17.3% | 4.6% | 2 / 2,209 / 20 | 99.9% / 99.8% / 96.2% |
| 근무 4시간 지연 | 16.3% | 2.9% | 37 / 2,703 / 229 | 99.9% / 91.0% / 96.2% |

수업 블록식에서 일별 최대 수전의 8일 평균은 MA-BEMS 984 kW, 숙련 BMS 970 kW였다. 한도를 넘은 시간은 MA-BEMS가 18분 적었으나 평균 일 피크는 약 14.5 kW 높았다. 기본 BMS의 늦은 근무 쾌적률에는 원래의 07:00~19:00 공조 시간이 영향을 준다. 타 건물로 이식하려면 해당 건물의 기상·계량·재실·설비와 현실적인 운영 규칙으로 보정한 후 다시 평가해야 한다.

## 입력 변동 확인

기본 사무 일정, 수업 블록식, 지연 일정에 각각 난수 시드 1·2를 적용해 숙련 운영자 BMS와 비교했다. 시드는 기상 및 방별 재실·예약, EV 도착, 수요반응 추첨을 바꾸며 같은 시드 안에서 두 제어기가 입력을 공유한다. 시드 1의 절감률은 4.47%, 4.55%, 3.23%, 시드 2는 4.07%, 3.98%, 2.70%다. 늦은 근무에서 절감폭이 줄어든 결과는 두 시드에서도 확인했다. 수업식 일정의 변화 방향은 시드에 따라 달랐다.

[요약 CSV](summary.csv)에는 기본 입력과 난수 시드 1·2의 조건별 결과가 있다.

## 재현

저장소 루트에서 Node.js 18 이상으로 실행한다.

```sh
node eval/followup/occupancy/run.cjs basic
node eval/followup/occupancy/run.cjs expert
node eval/followup/occupancy/run.cjs expert 1
node eval/followup/occupancy/run.cjs expert 2
```

`out/summary_*.json`에 집계를, 나머지 실행 JSON에 입력과 일별 지표를 저장한다. 기본 설정은 저장소의 기본 및 숙련 BMS 절감률과 편차가 0.001%p 미만인지 비교한다. 내장 재실 일정을 입력 시계열로 다시 공급했을 때 절감률 차이가 0.1%p 미만인지도 확인한다.
